# Реклама: скриншоты и карточки

Набор материалов для соцсетей и сайта снимается с **живого приложения**, а не
рисуется в макете. Один скрипт: `scripts/capture-ads.mjs`, запуск `npm run ads`.

Артефакты складываются в `marketing/ads/<YYYY-MM-DD>/` и в git не попадают
(`.gitignore`) — это генерируемый результат. В репозитории живёт только скрипт.

## Что снимает первый батч (RU, тёмная тема)

| Папка | Размер | Для чего |
|---|---|---|
| `clean/` | 1080×2400 PNG | экраны без обвеса: рамки, кропы и подписи накладываются в редакторе |
| `posts/` | 1080×1350 JPEG | лента Telegram / VK, 4:5 |
| `stories/` | 1080×1920 JPEG | сторис, Reels, шортсы, 9:16 |
| `landing/` | 1600×1000 JPEG | широкие блоки сайта и рекламные баннеры |

Посты: планка по секундомеру, волновой цикл, «всё в одном», ИИ-черновик.
Сторис: планка, цикл, прогресс. Баннеры: герой на главную и блок «что нового»
про время вместо повторов. Тексты к постам скрипт пишет в `README.md` рядом с
кадрами.

## Как это работает

1. `scripts/e2e-server.mjs` собирает прод-бандл и поднимает adapter-node на
   `:4310`. Supabase / AI / billing пустые — приложение грузится в локальном
   гостевом режиме, как в e2e, и не звонит наружу.
2. Контекст получает `addInitScript` с фикстурами в `localStorage`:
   `repdraft:plans`, `repdraft:sessions`, `repdraft:cycle`,
   `repdraft:athlete-profile`, `repdraft:onboarding`,
   `repdraft:session-ratings`. В истории есть и планка (`seconds`), и дорожка
   (`minutes`) — иначе главный экран не покажет фичу про время.
3. `clean/` снимается на 360×800 @3x → 1080×2400. Билдер идёт последним: он
   заполняет черновик и бейдж дока, который иначе попал бы в предыдущие кадры.
   У `/cycle` и `/progress` скрывается плавающий таббар — длинная страница
   продолжается под ним и в кадре выглядит обрезанной.
4. Экран ИИ снимается с моком `**/api/ai/plan` (GET + POST) через `page.route`:
   в тестовой сборке провайдер выключен намеренно.
5. Карточки собираются `page.setContent` поверх готовых PNG: рамка телефона,
   градиенты, кикер, заголовок, подпись, CTA. Палитра — локальные константы
   `BRAND` в скрипте, повторяют `src/lib/design/tokens.ts`.

## Добавить экран или карточку

- новый экран: строка в `screens` внутри `captureClean` (`{ file, path }`),
  при необходимости `hideTabbar: true`;
- новая карточка: `composeCard(page, { width, height }, post(...), путь)` и
  `dataUri(join(cleanDir, '<файл>.png'))`;
- новые демо-данные: фикстуры `PLANS` / `SESSIONS` в начале скрипта. Реальные id
  каталога: `0464` планка со скручиванием, `0684` бег на дорожке, `2135` планка
  с отягощением, `0025` жим лёжа, `3017` тяга Пендлея, `0043` приседания.

## Грабли

- Фальшивый «вырез» (notch) в рамке телефона закрывал заголовок экрана — убран,
  рамка и без него читается как телефон.
- `settle()` закрывает интро-шиты, cookie-плашку и backdrop: иначе они попадают
  в кадр. Новые оверлеи стоит добавлять туда же.
- Не снимать экраны с кастомными упражнениями: у локальных id нет картинок.
- RN-экраны Playwright не покрывает. Для нативных кадров нужен симулятор или
  dev build — это отдельная задача, веб-кадры для стора снимаются здесь.

## Проверки

Скрипт не входит в `npm run check` и e2e. Продуктовый код он не меняет; при
правках UI, которые видны на кадрах, гонять `npm run check` и профильные
spec'и (`hold-timer`, `live-weight-hint`).
