# Волновая периодизация (cycle)

Экран `/cycle` + карточка в `/workouts`: один мезоцикл на 8–12 недель, который
модулирует объём и интенсивность сохранённых планов. Идея — классическая схема
волновой периодизации: красная кривая объёма и синяя кривая интенсивности идут
в противофазе блоками по три недели, пик объёма на второй неделе, разгрузка на
третьей. Веб (SvelteKit) и RN используют один домен
(`src/lib/domain/cycle.ts`) и один ключ `repdraft:cycle`, но у каждого клиента
своё локальное хранилище.

## Модель волны

Порядок внутри блока: **интенсивность → объём → разгрузка**.

| Неделя блока | Тип | Объём | Интенсивность |
|---|---|---|---|
| 1 | `intensity` | 80 % | 112 % |
| 2 | `volume` | 118 % | 92 % |
| 3 | `unload` | 66 % | 80 % |

Проценты в таблице — схема волны для графика (от базы плана). Реальную
прескрипцию двигают дельты цели: интенсивная неделя убирает сет и повтор,
объёмная добавляет, разгрузка снимает минимум один сет и оставляет повторы и
отдых как в плане.

Недели цикла считаются от `startDate` (понедельник недели создания), ровно по
7 дней. После последней недели цикл «завершён», но остаётся в хранилище, пока
его не сбросят.

## Как волна ложится на план

`cycleWeekVariant(plan, week, cycle)` — чистый вариант плана на неделю:

- `plan.id` сохраняется (live/resume находят план), в имени префикс «нед. N»;
- `sets` / `reps` / `restSec` сдвигаются на дельты цели (`strength`, `muscle`,
  `cut`, `endurance`, `habit`) и клэмпятся через `inputLimits`; разгрузка
  гарантирует `−1` сет минимум;
- `groupId` / `altGroupId` и порядок упражнений не трогаются;
- лесенка `repsScheme` снимается, если изменилось число сетов.

### Подходы, повторы и вес

`cycleWeekTargets(plan, week, cycle, { sessions, equipmentFor })`
(`src/lib/domain/cycleTargets.ts`) — то, что неделя реально прописывает:

- `sets` / `reps` / `restSec` берутся из варианта недели, то есть те же числа,
  что увидит тренировка;
- `weightKg` считает `nextWeightHint` по истории атлета и целевым повторам
  недели: отказные подходы задают 1ПМ, отказ на верхнем весе держит нагрузку,
  ранний отказ снижает на шаг;
- `barKg` и шаг — из каталога (`equipmentFor`): обычная штанга 20 кг,
  EZ/SZ-гриф 10 кг, шаг 2.5 кг; гантели 2 кг, гири 4 кг. Вес не опускается ниже
  пустого грифа;
- упражнение без истории получает подходы и повторы, а `weightKg` остаётся
  `null` — выдумывать нагрузку нельзя.

На экране недели по каждому упражнению видно `подходы × повторы · вес` и
«гриф N кг» у штанги. Вес попадает в стартующую сессию (`cycleTargetWeights` ->
`live.startFromPlan(variant, { weights })`), а не в сохранённый шаблон.

Старт недели идёт через `live.startFromPlan(variant, { lockPrescription: true,
weights })`, как «Сегодня» в `planTune`: сохранённый план не перезаписывается.
Заблокированная прескрипция не даёт истории переписать подходы и повторы недели —
она может только заполнить пустой вес. Поэтому в истории видно
«нед. 3 · Грудь + трицепс», а `planId` остаётся исходным — по нему и считается
прогресс цикла.

## Данные

- Ключ `repdraft:cycle`, один активный цикл, **только локально** (как
  `athleteProfile`). Облачной синхронизации нет: нет таблицы и RLS.
- Веб: стор `src/lib/stores/cycle.ts` над `localStorage`; RN: `mobile/src/state/cycle.ts`
  над AsyncStorage (`kv`).
- Прогресс не хранится: он выводится из истории (завершённые сессии,
  `planId ∈ cycle.planIds`, дата внутри недели).
- Сброс цикла удаляет только запись цикла; планы и тренировки остаются.

## Клиенты

- **Web**: `src/routes/cycle/+page.svelte` (настройка, график, недели), карточка
  в `/workouts`, бейдж в шапке главной, чип в превью плана.
- Карточка в `/workouts` — тизер-строка (~64px), а не превью графика: шапка
  «Волновой цикл» + «Неделя N из M» акцентом, вторая строка «Тренировок: X из Y»
  и шеврон. Имя цикла выводится отдельной строкой только если пользователь его
  переименовал (по умолчанию оно совпадает с шапкой). График и список недель
  живут на `/cycle`; на самой странице цикла заголовок в карточке-сводке тоже
  скрыт, когда имя равно названию экрана.
- **RN**: `mobile/app/cycle.tsx` + `mobile/src/cycle/useCycleScreen.ts`, SVG-график
  `mobile/src/cycle/CycleWaveChart.tsx` (react-native-svg, `chartVolume` из
  палитры), карточка в табе «Тренировки», бейдж в `PlanHeroCard`, чип в
  `mobile/app/plan/[id].tsx`. Неделя стартует так же — вариант + `lockPrescription`.

## Два уровня аккордеона (оба клиента)

Страница цикла — не простыня: открыта одна неделя, и внутри неё **один день**.

- Неделя: строка «Неделя N · тип» + «объём / интенсивность» + «done из planned»
  (`cycle-week__head`, `aria-expanded`).
- День (план): строка-аккордеон `cycle-week__plan-toggle` — имя плана + мета
  (`home.pillExercises`, «7 упражнений») + шеврон; справа отдельно CTA «Начать»
  (или «Готово»/«нет плана»). Кнопка старта **не** вложена в кнопку-тоггл.
  Пока день свёрнут, прескрипция (`{@const targets = ...}`, список
  `cycle-week__rx`) не считается и не рендерится вообще.
- Состояния: `expandedWeek` и `expandedDay` (`planId`); переключение недели
  сбрасывает открытый день, создание/сброс цикла — оба. По умолчанию открыта
  текущая неделя, все дни свёрнуты.
- Правило: **не возвращать** всегда-раскрытые дни. Раньше неделя печатала все
  упражнения всех дней сразу (~7 строк × 4 дня), и экран под графиком был стеной
  цифр; вес/повторы нужны перед стартом, а не как обзор.

## Проверки

`npm run check:domain` гоняет `runCycleSelfCheck` (порядок волн, проценты, разгрузка,
клэмпы, сохранение групп/дублей упражнений, границы недель, фильтр сессий,
нормализация хранилища) и `runCycleTargetsSelfCheck` (подходы/повторы недели,
отказ держит вес, EZ-гриф не ниже 10 кг, пустая история не выдумывает вес,
карта весов для старта). Перед «готово» — `npm run check:parity` (токены,
версии, домен, веб + RN тайпчек).
