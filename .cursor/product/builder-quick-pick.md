# Быстрый подбор в билдере (`/builder/equipment`)

Пустой редактор раньше предлагал только каталог: новичок должен знать название
упражнения. Три шага снимают этот барьер: что есть под рукой -> какие мышцы ->
короткий список упражнений, откуда они добавляются в обычный черновик.

## Поток

| Шаг | Что видно | Данные |
|-----|-----------|--------|
| 1. Оборудование | чипы с количеством упражнений, «свой вес» первый; пустой выбор = «любое» | `equipmentFacets(catalog)` |
| 2. Мышцы | зоны каталога (`Ноги` = бёдра + голени), счётчик под текущий инвентарь | `hubCatalogZones`, `catalogZoneBodyParts` |
| 3. Упражнения | до 24 карточек, самые популярные сверху, кнопка «плюс» кладёт в `draft` | `pickExercisesForKit(catalog, { equipment, bodyParts })` |

Дальше «Готово» возвращает в `/builder` с уже заполненным черновиком; подходы,
повторы и суперсеты настраиваются там же. Отдельного хранилища у визарда нет:
единственный побочный эффект это обычный `repdraft:draft`.

## Правила

- Зоны каталога: общий словарь всего продукта, не только визарда:
  `src/lib/domain/bodyZones.ts` (`legs` = бёдра + голени). Доли на `/progress`,
  сводка тренировки и подсказки тренера агрегируют подходы по зонам
  (`sessionSetsByBodyPart` / `sessionVolumeByBodyPart`), поэтому «Голени» никогда
  не стоят отдельной строкой рядом с «Ногами», а подбор упражнения под зону
  (`pickCatalogExerciseForBodyPart`) умеет брать и зону, и сырой `body_part`.
  Правило закреплено в `npm run check:domain` (`runTrainingLoadSelfCheck`,
  `runProgressOverviewSelfCheck`).
- «Свой вес» доступен всегда: если инвентарь не выбран или выбран частично,
  бодивейт остаётся запасным вариантом (`exerciseMatchesEquipment`).
- Каталог грузится на клиенте (`loadExerciseIndexWithCustoms`); на тёплом переходе
  данные берутся из `peekExerciseIndex`, поэтому шаг открывается без спиннера.
- Фильтрация и сортировка живут в `src/lib/domain/exercisePick.ts` и проверяются в
  `npm run check:domain` (`runExercisePickSelfCheck`). UI только рисует результат.
- Список ограничен 24 карточками: это подбор, а не каталог. Уточнение фильтров на
  шагах 1-2 делает выдачу точнее.
- Шаг 3 переиспользует общий список карточек упражнений
  (`.exercise-list--cards`, бывший `catalog-exercise-list`): карточка с рамкой,
  превью 4.75rem, круг для добавления. В пикере строки ниже (нет 128px
  `min-height` базового списка), фильтры показаны чипами, у добавленного
  упражнения рамка и фон подсвечены акцентом, а плюс становится залитым чеком.
- Сводка фильтров над списком не текст, а кнопки: тап по «Гантели» открывает шаг 1,
  тап по «Грудь» - шаг 2, выбранные значения остаются. «Сбросить фильтры» только
  расширяет выдачу и не уводит со шага 3.
- Выбранный чип рисует общий `AppChip` (`is-active`): заливка `--color-accent-muted`
  и акцентный текст. Прописано один раз в `controls.css`, потому что базовая краска
  `.btn-secondary` идёт с `!important` и без этого выбранный фильтр выглядел как
  невыбранный (касалось и `/cycle`, и `/feedback`).
- Иконка плюса центрируется гридом внутри 15px обёртки: раньше `display:block`
  оставлял глиф в левом верхнем углу кнопки. Регресс держит тест
  «the add glyph sits dead centre in its button».

## Что из этого переиспользует RN

Полного визарда в мобильном клиенте нет: там свой пикер с поиском. Общие правила
берутся из того же домена, чтобы фильтры не разъезжались:

- `equipmentFacets(catalog, 10)` рисует второй ряд чипов под мышцами
  (`mobile/src/builder/BuilderPicker.tsx`), фильтр уходит в
  `filterExercises(..., { equipment })`.
- «Свой вес» и совпадение инвентаря - тот же `exerciseMatchesEquipment`.
