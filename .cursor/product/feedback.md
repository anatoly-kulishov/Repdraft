# Обратная связь (`/feedback`)

Публичная страница без входа: ошибка, предложение или другой отзыв уходит
письмом на ящик владельца. Ничего не сохраняется в приложении, поэтому форма
работает и до регистрации, и в гостевом режиме.

## Поток

| Шаг | Что происходит |
|-----|----------------|
| Форма | тип (`bug` / `idea` / `other`), сообщение до 2000 символов, необязательная почта для ответа |
| Клиент | `validateFeedback` из `src/lib/domain/feedback.ts`: те же правила, что у сервера |
| `POST /api/feedback` | honeypot, проверка `Origin`, лимит 5 сообщений в час на IP, затем `nodemailer` |
| Письмо | тема `[Repdraft] <тип>: <первые слова>`, в теле страница, версия, язык, UA и текст |

Вход в аккаунт не требуется. Подписанному пользователю поле почты подставляется
из профиля, но он может его изменить или очистить.

## Настройка (RF VPS)

`.env` на сервере, те же ключи в `.env.example`:

```dotenv
FEEDBACK_SMTP_HOST=smtp.yandex.ru
FEEDBACK_SMTP_PORT=465
FEEDBACK_SMTP_SECURE=true
FEEDBACK_SMTP_USER=you@yandex.ru
FEEDBACK_SMTP_PASS=<app password>
FEEDBACK_EMAIL_TO=you@yandex.ru
FEEDBACK_EMAIL_FROM=you@yandex.ru
```

- Пароль приложения выдается в Яндекс 360 (Настройки -> Безопасность -> Пароли
  приложений). Обычный пароль ящика SMTP не подходит.
- В самом ящике должен быть включен доступ почтовых программ: Почта -> Настройки
  -> «Почтовые программы» -> «Разрешить доступ к почтовому ящику с помощью
  почтовых клиентов» (IMAP и пароли приложений). Пока галочка снята, даже верный
  app-пароль получает `535 5.7.8 This user does not have access rights to this
  service`, а IMAP отвечает `AUTHENTICATIONFAILED ... or IMAP is disabled`.
- `FEEDBACK_EMAIL_TO` по умолчанию берётся из `PUBLIC_PRIVACY_CONTACT_EMAIL`.
- `FEEDBACK_EMAIL_FROM` по умолчанию равен SMTP-логину: Яндекс пропускает только
  свои адреса и алиасы.
- Без `FEEDBACK_SMTP_USER` / `FEEDBACK_SMTP_PASS` форма отвечает «временно
  недоступна» и показывает почту из `PUBLIC_PRIVACY_CONTACT_EMAIL`, чтобы отзыв
  не потерялся.

После правки `.env` перезапустить контейнер (`docker compose up -d`) и отправить
тестовое сообщение с продакшена.

Проверка creds без браузера: `npm run check:feedback` показывает, какие ключи
заданы (без значений), а `npm run check:feedback -- --send` логинится в SMTP и
шлёт одно тестовое письмо.

## Антиспам

- Скрытое поле `website` (honeypot): заполненное, молча получает `ok` и письмо не
  уходит.
- `Origin` проверяется только когда браузер его прислал: чужой сайт получает 403,
  curl и нативное приложение (без `Origin`) проходят.
- Лимит `createRateLimitWindow`: 5 писем в час на IP, ответ 429 с `Retry-After`.
  Счётчики живут в памяти процесса и сбрасываются при рестарте.
- Длины полей ограничены и на клиенте, и на сервере; заголовок письма собирается
  из одной строки, чтобы исключить инъекцию заголовков.
- IP в письмо не попадает: он нужен только лимитеру.

## Приватность

Форма собирает текст сообщения, необязательный адрес для ответа, путь экрана,
версию приложения, язык и user-agent. Это нужно, чтобы воспроизвести баг.
Адрес используется только для ответа и не пишется в localStorage. Ссылка на
политику конфиденциальности стоит под кнопкой отправки.

## Проверки

- `npm run check:domain` -> `runFeedbackSelfCheck` (валидация, очистка текста,
  тема письма) и `runRateLimitWindowSelfCheck` (лимит и окно).
- `tests/e2e/feedback.spec.ts`: пустая форма не отправляется, валидное сообщение
  уходит на `/api/feedback` с типом и текстом, успех показывается без перезагрузки.
- `public-content.spec.ts` включает `/feedback` в обход публичных роутов.
